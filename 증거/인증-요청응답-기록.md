## 3. 세션으로 인증 상태 유지 (로그아웃 전후 비교)

- 방식: **서버 세션**. 로그인하면 서버가 무작위 32바이트 값을 만들어 `HttpOnly; SameSite=Strict` 쿠키로 주고, 서버 DB에는 그 값의 SHA-256 해시와 만료 시각만 저장합니다. 값은 주소(URL)에 들어가지 않습니다.

### 3-1 같은 주소·같은 방식(GET /api/tasks)으로, 로그아웃 전과 후
```
> [로그아웃 전] GET /api/tasks  Cookie: sid=NfZb…생략
< 200   []
```
```
> [로그아웃] POST /api/auth/logout  Cookie: sid=NfZb…생략  본문: {}
< 200   {"ok":true}  Set-Cookie: sid=; HttpOnly; SameSite=Strict; Path=/; Secure; Max-Age=0
```
```
> [로그아웃 후, 같은 쿠키 값으로] GET /api/tasks  Cookie: sid=NfZb…생략
< 401   {"error":"로그인이 필요합니다."}
```
- ✅ **C109/C110** 같은 요청이 로그아웃 전 200, 로그아웃 후 401. 달라진 것은 로그아웃 여부뿐이다
- ✅ **C112** 세션 값은 응답 본문·주소에 나오지 않고 쿠키로만 간다
- ✅ **C111** 쿠키 Max-Age=604800 (7일) 이다
- 서버에 저장된 A의 세션 한 줄 (값 자체가 아니라 해시 앞 8글자만):
```
{"hash8":"9a570520","created_at":"2026-11-19T08:42:38.589Z","expires_at":"2026-11-26T08:42:38.589Z","span":"7 days"}
```

### 3-2 비밀번호를 바꾸면 이전에 발급한 세션이 무효가 된다

- 이 방식은 서명용 비밀키를 쓰지 않습니다(세션 값은 무작위값이고 서버 DB 조회로 확인). 비밀값은 DB 접속 주소(`DATABASE_URL`) 하나이고 서버 환경변수에만 있습니다.

### 4-7 위 거절을 만드는 소스 위치
- `lib/handler.js` — `route()`: 로그인한 사용자(`user`)가 없으면 401. 있으면 모든 조회·쓰기에 `user.id`를 넘깁니다.
- `lib/handler.js` — `getTask()`, `updateTask()`, 삭제(`route()` 안 DELETE), `completeTask()`, `reopenTask()`, `addRun()`: SQL의 `where id = $1 and user_id = $2` 조건. 남의 자료는 "없음"으로 보여 404.
- `lib/handler.js` — `taskFilterSql()`: 목록·돌아보기가 모두 거치는 곳이며 `t.user_id = $1` 조건을 항상 붙입니다.
- 주소·헤더·본문의 계정 값은 읽지 않습니다. 주인은 오직 쿠키 세션(`lib/auth.js` `currentUser()`)으로 정합니다.
